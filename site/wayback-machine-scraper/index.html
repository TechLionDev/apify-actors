Wayback Machine Scraper: Snapshots, History & Dates

Wayback Machine scraper: list archived snapshots of any URL or domain with dates, status codes and links. Closest capture, first/last capture. No login.

Run it on ApifyAll 23 TechLion Dev Actors$0.30 / 1,000 snapshots

A first test run is usually under a cent. No login to the source site. Pay only for the results you get. Built and maintained by TechLion Dev.

Wayback Machine Scraper lists the archived snapshots of any web page or domain kept by the Internet Archive's Wayback Machine (archive.org). For every capture you get the date, the HTTP status code, the file type, a content fingerprint and a ready-to-open archive link. It uses the Archive's official public CDX (capture index) and availability endpoints with plain HTTP: no browser, no login and no proxy.

It is for SEO (search engine optimization) specialists, domain investors, journalists and researchers, lawyers collecting evidence of past web content, brand and competitor analysts, and AI (artificial intelligence) agents that need the history of a website.

  • See how a site changed: one capture per month or year, or only captures where the content really changed.
  • Check a domain's past: first capture, last capture and every year that has captures (great before buying an expired domain).
  • Find lost pages: list every archived URL under a domain or path, then open the archive link for each.
  • Prove what a page said on a date: get the capture closest to any date you choose.

What data does it extract?
🔗 Archived page address and your query 📅 Capture date and time (UTC) and year
🚦 HTTP status code (200, 301, 404...) 📄 File type (HTML, PDF, image...)
🔑 Content fingerprint (same value = same content) 📦 Archived size in bytes
👁️ Link to view the capture 🧾 Link to the raw capture without the archive toolbar

Three modes

  • Snapshots: one row per capture, with filters and a maximum per URL.
  • Closest: one row per URL and date, the capture nearest to that date.
  • Summary: one row per URL with first capture, last capture and the years that have captures.

Why this scraper?

  • Cheap and simple: $0.30 per 1,000 rows, plus a tiny start fee. Filters are free.
  • Official endpoints: the same public index the Archive documents. It reads politely at about one request per second and backs off automatically when the Archive asks it to slow down.
  • Many URLs per run: domain, host or path-prefix matching covers whole sites.
  • Control your cost: a maximum per URL, and the Actor stops cleanly at your maximum cost per run.

Input

  • URLs or domains: one per line, such as example.com or example.com/pricing. Empty runs a sample for example.com.
  • Mode: Snapshots, Closest or Summary.
  • Match type: Exact URL, Prefix (everything under a path), Host, or Domain (including subdomains).
  • From date / To date: limit the period (2020, 2020-06 or 2020-06-15).
  • Status codes / File types: for example 200, or text/html.
  • Collapse near-duplicates: keep one capture per day, month or year, or only when the content changed.
  • Newest first: list recent captures first.
  • Max snapshots per URL: a cap on rows (and cost) for each URL.
  • Closest to dates: only for Closest mode.

Invalid entries are skipped with a warning; if nothing valid is left, the run stops with a clear message.

Example input

{
    "urls": ["example.com"],
    "mode": "snapshots",
    "collapse": "year",
    "statusCodes": ["200"],
    "maxSnapshotsPerUrl": 25
}

Output

One row per capture. You can download the dataset as JSON, CSV, Excel, XML or HTML, or read it through the API. A RUN_SUMMARY record lists each URL, how many captures were seen and saved, and any error.

{
    "query": "example.com",
    "url": "http://example.com/",
    "timestamp": "2020-01-01T00:00:12Z",
    "timestampRaw": "20200101000012",
    "year": 2020,
    "statusCode": 200,
    "mimeType": "text/html",
    "digest": "HT2DYGA5UKZCPBSFVCV3JOBXGW2G5UUA",
    "sizeBytes": 1792,
    "snapshotUrl": "(archive link to view the capture)",
    "rawUrl": "(archive link to the raw capture)"
}

How to use it

  1. Open the Actor in Apify Console and paste a URL or domain (or keep the example.com sample).
  2. Pick a mode: Snapshots (full history), Closest (nearest capture to a date), or Summary (first/last capture and years covered).
  3. Click Start. A short list finishes in a few seconds.
  4. Download the dataset as CSV, Excel or JSON, or follow the archive links to view a capture.
  5. To run it on a schedule or from your own code, use the Apify API or an integration (see below).

How much does it cost?

Pay per event: $0.0003 per saved row (Bronze to Diamond plan discounts apply) plus a very small start event. A run with 1,000 rows costs about $0.30. Rows removed by your filters are not charged. Set a maximum cost per run and the Actor stops cleanly when it is reached.

Use cases

  • Audit how a landing page or pricing page changed over time for SEO or a competitor review.
  • Check an expired or newly purchased domain's archive.org history before you invest.
  • Recover a lost page: list every archived URL under a domain or path, then open the capture.
  • Collect evidence of what a public page said on a given date (closest-capture mode).
  • Feed Wayback Machine snapshot dates and links into a research or AI pipeline.
